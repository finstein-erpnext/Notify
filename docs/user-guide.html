User Guide

Desktop & mobile push for Frappe

Notify turns your Frappe/ERPNext bell notifications into Outlook-style desktop pop-ups and phone lock-screen alerts — powered by your own free Firebase project.

Applies to Frappe / ERPNext v15+ Audience Administrators & end users Version 1.0

Overview

Whenever something appears in the Frappe bell — a mention, an assignment, an approval, a workflow update — Notify also delivers it to the recipient's registered browsers and phone:

  • Desktop pop-ups — an alert at the top of the screen (like Outlook), with sound, even when the Frappe tab isn't in front.
  • Mobile lock-screen alerts — pushed to an employee's phone through the Frappe HR (ESS) app.
  • Role-based fan-out — notify everyone with access to a doctype (e.g. every approver of a Job Opening), not just one person.

It runs on any Frappe site and works with any app — ERPNext, HR, LMS, or your own custom apps — because it hooks into the standard notification system.

How it works

Notify sends messages directly to Firebase Cloud Messaging (FCM) — Google's free push service. You create your own Firebase project and paste its credentials into the settings screen. There is no third-party relay and no per-message cost.

Requirements

  • A Frappe/ERPNext v15+ site where you are a System Manager.
  • The site served over HTTPS (browsers require it for notifications; http://localhost also works for local testing).
  • A Google account to create a free Firebase project.
  • For mobile alerts: the Frappe HR (HRMS) app installed on the site.

1Create a Firebase project

You do this once. Everything here is on Firebase's free plan.

  1. Create the projectGo to console.firebase.google.com → Add project. Name it and finish (you can skip Google Analytics).
  2. Add a Web appOn the project home click the Web icon </> and register it (no Hosting needed). Firebase shows a firebaseConfig snippet — keep it handy for step 3.
  3. Generate the VAPID keyGear ⚙️ → Project settings → Cloud Messaging → Web Push certificates → Generate key pair. Copy the key.
  4. Download the Service AccountProject settings → Service accounts → Generate new private key. A .json file downloads — keep it secret.

2Install the app

On your bench:

bench get-app notify <repository-url>
bench --site your-site install-app notify

The required firebase-admin Python package installs automatically with the app.

3Configure settings

Open Notify Settings (search for it in the Awesomebar).

  1. Enable NotifyLeave the master switch ticked.
  2. Fill the Firebase web configClick Paste firebaseConfig (top-right), paste the snippet from step 1, and choose Fill Fields — API Key, Auth Domain, Project ID, Sender ID and App ID fill in automatically.
  3. Add the VAPID keyPaste the Web Push key into VAPID Public Key.
  4. Add the Service Account JSONOpen the downloaded .json file and paste its full contents into Service Account JSON.
  5. SaveYou'll see a green “Push is configured and ready” banner.

The web config values are public identifiers. The Service Account JSON is secret — it is stored only on this site and never sent anywhere else.

4Turn on desktop notifications

Each user enables notifications once per browser:

  1. Open the DeskA banner appears at the top: “Turn on notifications…”.
  2. Click “Enable Notifications”The browser asks for permission — click Allow.

From then on the device registers itself silently on every login — no manual token handling ever. Each different browser or computer needs its own one-time Allow.

Already blocked notifications? The banner shows how to re-allow: click the lock/tune icon in the address bar → Site settings → set Notifications to Allow → reload.

5Turn on mobile (ESS) notifications

Requires the Frappe HR app installed and the site on HTTPS.

Administrator — once

  • In Notify Settings, tick Enable Mobile / ESS Push.
  • Set Public Site URL to the HTTPS address employees use (or leave blank to auto-detect) and save.

Each employee — once, on their phone

  • Open the HR app URL in the phone browser.
  • Install it — Android (Chrome): menu → Add to Home screen; iPhone (Safari): Share → Add to Home Screen (required on iPhone). Open it from the new icon.
  • Go to Profile → Settings → Enable Push Notifications → Allow.

Everyday use

There's nothing to do day-to-day — it works in the background. A notification is delivered whenever the recipient would get a bell notification, for example when someone @mentions or assigns them, a document is shared, or a workflow needs their approval. Click any pop-up to open the related document and act on it.

To check your setup anytime, open Notify Settings and click Send Test Notification.

Role-based rules (fan-out)

By default every bell notification goes to its intended recipient. To instead notify everyone who has access to a doctype when an event happens, create a Notify Rule:

FieldMeaning
Reference DocTypeThe doctype to watch, e.g. Job Opening.
Trigger EventNew Document · On Update · On Submit · Workflow State Reached.
Workflow StateFor workflow triggers — e.g. notify only at Pending CEO Approval.
NotifyAll Users With Access (everyone whose role can read the doctype) or Users With Specific Roles.
TemplatesOptional Jinja title / body / link, plus a sound toggle.

Access is always enforced. Every recipient is checked individually with Frappe's own permission engine before sending, so a user can never receive a push about a record their role or user-permissions don't allow them to open.

Example. Rule on Job Opening, Trigger Workflow State Reached → Pending CEO Approval, Notify Users With Specific Roles → CEO: every CEO is alerted the moment a Job Opening reaches that state.

Devices & logs

Every browser or phone that enables notifications appears in Notify Device (user, platform, last seen). You normally never touch this list — it fills and cleans itself: devices register automatically, invalid tokens are removed, and unused devices are cleared by a daily job.

Notify Log records every send (who, what, status) for auditing and troubleshooting.

Troubleshooting

The green “ready” banner doesn't appear

Make sure all Firebase web fields, the VAPID key, and the full Service Account JSON are filled, then Save.

A user sees no “Enable” banner

They've already granted permission (nothing to do), or the site isn't on HTTPS — notifications require HTTPS (or localhost).

Everything says “ready”, but pop-ups don't arrive (desktop)

The most common cause on office networks is a firewall blocking Google's push connection. Web push is delivered over a persistent link to Google on ports 5228–5230. To confirm, open chrome://gcm-internals/ and check Connection State — if it isn't Connected (e.g. “WAITING FOR BACKOFF”), the network is blocking it.

Fix. Ask IT to allow outbound to Google FCM (mtalk.google.com, ports 5228–5230, plus 443), or test on a different network (e.g. a phone hotspot) to confirm.

The phone gets nothing

  • iPhone: the app must be installed to the Home Screen (iOS 16.4+); web push doesn't work in a plain Safari tab.
  • Check the app is allowed to notify and the phone isn't in Do Not Disturb.
  • The same port-5228 block can apply on office Wi-Fi; phones usually work on mobile data.

No sound

Ensure Play Sound is on. A custom sound plays for the desktop pop-up while the tab is in front; background and mobile alerts use the device's own notification sound.

FAQ

Do I have to register each user's device manually?

No. Users allow notifications once per browser/phone; devices register themselves automatically after that.

Can I enable notifications for everyone by default?

Browsers require each user to allow once — it can't be pre-granted, except by an IT-managed browser policy (Chrome Enterprise / MDM) that auto-allows your site's URL.

Does it cost anything?

No. It uses your own free Firebase project and sends directly — no relay, no per-message fee.

Which apps does it work with?

Any Frappe app, because it hooks into the standard bell (Notification Log) — ERPNext, HR, LMS, and custom apps.

Limits & notes

  • Desktop pop-ups appear when the browser is running (the tab may be closed/minimised). A pop-up with no browser open at all needs a native desktop app and is out of scope.
  • iPhone web push requires the app installed to the Home Screen (iOS 16.4+).
  • Custom sound applies to the desktop foreground pop-up; background and mobile alerts use the device's default sound.
  • HTTPS is required for notifications on real devices.
  • Networks that block Google's push ports (5228–5230) prevent delivery on that network — use an allowed network or ask IT to open those ports.

Configure once in Notify Settings, have each user click Allow, and alerts start flowing. For issues, check Notify Log and the troubleshooting section above.
